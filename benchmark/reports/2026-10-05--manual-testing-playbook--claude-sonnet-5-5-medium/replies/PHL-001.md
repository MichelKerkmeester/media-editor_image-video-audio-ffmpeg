**Limit first:** this Project can't run ffmpeg and no Media Editor tools are connected, so nothing ran. What follows is guidance only. The HLS recipe also writes **no audio** (`-an`), and a keynote is mostly speech. Used as-is, the stream would play silent.

Keynote recordings are usually long and large. A full four-rung encode of a multi-gigabyte file can take tens of minutes and several GB of disk. The lighter route is to run the 10-second test first, then drop the 1080p rung if you need a smaller ladder. The full run is your call.

**Run this** (set `INPUT` to your keynote file). I used `keynote-hls-ladder` as the working name, so change it if you like:

```bash
ffmpeg -version | head -n 1 && ffmpeg -encoders | grep libx264

# Optional 10-second test first
ffmpeg -i "INPUT.mp4" -t 10 -vf "scale=1920:1080" -c:v libx264 -preset fast -crf 23 -maxrate 2500k -an test_output.mp4

# Full ladder
mkdir -p "media files/export/001 - keynote-hls-ladder"
ffmpeg -i "INPUT.mp4" \
  -filter_complex "[0:v]split=4[v1][v2][v3][v4]; \
  [v1]scale=w=1920:h=1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2[v1out]; \
  [v2]scale=w=1280:h=720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2[v2out]; \
  [v3]scale=w=854:h=480:force_original_aspect_ratio=decrease,pad=854:480:(ow-iw)/2:(oh-ih)/2[v3out]; \
  [v4]scale=w=640:h=360:force_original_aspect_ratio=decrease,pad=640:360:(ow-iw)/2:(oh-ih)/2[v4out]" \
  -map "[v1out]" -c:v:0 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 -crf 23 -maxrate:v:0 2500k -bufsize:v:0 5000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v2out]" -c:v:1 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 -crf 23 -maxrate:v:1 1500k -bufsize:v:1 3000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v3out]" -c:v:2 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 -crf 23 -maxrate:v:2 800k -bufsize:v:2 1600k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v4out]" -c:v:3 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 -crf 23 -maxrate:v:3 500k -bufsize:v:3 1000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -an -f hls -hls_time 2 -hls_playlist_type vod -hls_flags independent_segments -hls_segment_type mpegts \
  -hls_segment_filename "media files/export/001 - keynote-hls-ladder/%v/segment_%03d.ts" \
  -master_pl_name "master.m3u8" \
  -var_stream_map "v:0,name:1080p v:1,name:720p v:2,name:480p v:3,name:360p" \
  "media files/export/001 - keynote-hls-ladder/%v/playlist.m3u8"
```

Adjust these before running:
- **Folder number:** use the next free three-digit number in `media files/export/`. `001` is right only if it holds no numbered folder yet.
- **Frame rate:** `-g 48` and `-keyint_min 48` assume 24 fps with 2-second segments. For 30 fps use 60, and for 25 fps use 50.
- **Resolution:** a source below 1080p gets upscaled and padded by this recipe. Check its size with `ffprobe` first and remove any rung taller than the source.
- **Audio:** if the recording has speech, tell me and I'll give you the command to extract it as a separate AAC file to ship beside the stream. The ladder recipe itself can't carry an audio track.

Your site player loads `master.m3u8`. Safari plays it natively, and Chrome, Firefox and Edge need HLS.js.
