## A heads-up on the 8 GB file

This is a very large input. A four-rung ladder re-encodes the whole file four times in one pass. Expect tens of minutes to hours, depending on your Mac and the footage codec (ProRes or camera RAW is slower to decode). The output should be a few hundred MB to about 1–2 GB, and you'll need that much free disk space.

A lighter path first:
- **Test run:** encode the first 10 seconds before committing to the full file.
- **Fewer rungs:** drop the 1080p rung, or keep only 720p, 480p and 360p, to cut the time and size.
- **Split the footage:** if you only need part of it, trim it first.

The full ladder is your call, but run the test first.

## Run this

Set `INPUT` to your file path. `001` is a guess at the next free number in `media files/export/`, so change it if that folder already holds numbered folders. The name `website-footage-hls` is a working name you can change.

```bash
INPUT="/path/to/your-raw-footage.mov"
OUT="media files/export/001 - website-footage-hls"

# 1. Confirm ffmpeg and libx264 exist
ffmpeg -version | head -n 1
ffmpeg -encoders | grep libx264

# 2. Test on the first 10 seconds
ffmpeg -i "$INPUT" -t 10 -vf "scale=1920:1080" \
  -c:v libx264 -preset fast -crf 23 -maxrate 2500k -an /tmp/hls_test.mp4

# 3. Full ladder
mkdir -p "$OUT"
ffmpeg -i "$INPUT" \
  -filter_complex "[0:v]split=4[v1][v2][v3][v4]; \
  [v1]scale=w=1920:h=1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2[v1out]; \
  [v2]scale=w=1280:h=720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2[v2out]; \
  [v3]scale=w=854:h=480:force_original_aspect_ratio=decrease,pad=854:480:(ow-iw)/2:(oh-ih)/2[v3out]; \
  [v4]scale=w=640:h=360:force_original_aspect_ratio=decrease,pad=640:360:(ow-iw)/2:(oh-ih)/2[v4out]" \
  -map "[v1out]" -c:v:0 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 \
    -crf 23 -maxrate:v:0 2500k -bufsize:v:0 5000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v2out]" -c:v:1 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 \
    -crf 23 -maxrate:v:1 1500k -bufsize:v:1 3000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v3out]" -c:v:2 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 \
    -crf 23 -maxrate:v:2 800k -bufsize:v:2 1600k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v4out]" -c:v:3 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 \
    -crf 23 -maxrate:v:3 500k -bufsize:v:3 1000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -an \
  -f hls -hls_time 2 -hls_playlist_type vod \
  -hls_flags independent_segments -hls_segment_type mpegts \
  -hls_segment_filename "$OUT/%v/segment_%03d.ts" \
  -master_pl_name "master.m3u8" \
  -var_stream_map "v:0,name:1080p v:1,name:720p v:2,name:480p v:3,name:360p" \
  "$OUT/%v/playlist.m3u8"
```

Two things in this recipe may not suit your footage:
- **No audio:** `-an` removes the audio track, so the HLS ladder is silent. If the site video needs sound, tell me and I'll suggest an alternative.
- **Frame rate:** `-g 48` assumes 24 fps with 2-second segments. If the footage is 25, 30 or 60 fps, check it with `ffprobe` and set `-g` and `-keyint_min` to fps × 2. For example, use 60 at 30 fps.

## Result lands in

`media files/export/001 - website-footage-hls/` contains:
- `master.m3u8`, which is the file your site's player loads
- `1080p/`, `720p/`, `480p/` and `360p/`, each with a `playlist.m3u8` and `segment_*.ts` files
