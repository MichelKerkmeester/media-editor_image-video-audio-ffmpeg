For an 8GB "raw" source, two things matter before the command: the actual codec (camera raw formats like ProRes RAW, BRAW, R3D, or even standard ProRes 422 all decode differently) and which of the four HLS renditions you actually need for the website — not every site needs 1080p+720p+480p+360p.

Standard multi-quality HLS ladder (adjust `INPUT_VIDEO` and `OUTPUT_DIR` to your paths):

```bash
ffmpeg -i INPUT_VIDEO.mov \
  -filter_complex "[0:v]split=4[v1][v2][v3][v4]; \
  [v1]scale=w=1920:h=1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2[v1out]; \
  [v2]scale=w=1280:h=720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2[v2out]; \
  [v3]scale=w=854:h=480:force_original_aspect_ratio=decrease,pad=854:480:(ow-iw)/2:(oh-ih)/2[v3out]; \
  [v4]scale=w=640:h=360:force_original_aspect_ratio=decrease,pad=640:360:(ow-iw)/2:(oh-ih)/2[v4out]" \
  -map "[v1out]" -c:v:0 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 \
    -crf 23 -maxrate:v:0 2500k -bufsize:v:0 5000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v2out]" -c:v:1 libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 \
    -crf 23 -maxrate:v:1 1500k -bufsize:v:1 3000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v3out]" -c:v:2 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 \
    -crf 23 -maxrate:v:2 800k -bufsize:v:2 1600k -g 48 -keyint_min 48 -sc_threshold 0 \
  -map "[v4out]" -c:v:3 libx264 -preset fast -tune fastdecode -profile:v baseline -level 3.1 \
    -crf 23 -maxrate:v:3 500k -bufsize:v:3 1000k -g 48 -keyint_min 48 -sc_threshold 0 \
  -an -f hls -hls_time 2 -hls_playlist_type vod -hls_flags independent_segments \
  -hls_segment_type mpegts \
  -hls_segment_filename "OUTPUT_DIR/%v/segment_%03d.ts" \
  -master_pl_name "master.m3u8" \
  -var_stream_map "v:0,name:1080p v:1,name:720p v:2,name:480p v:3,name:360p" \
  OUTPUT_DIR/%v/playlist.m3u8
```

**Result lands in:** `export/NNN - hls-conversion/` in your CLI runtime, with `master.m3u8` plus `1080p/`, `720p/`, `480p/`, `360p/` subfolders each holding a `playlist.m3u8` and `segment_*.ts` files.

**Check this:** run `ffprobe OUTPUT_DIR/1080p/playlist.m3u8` per rendition to confirm codec/resolution, confirm segment counts look right for the source duration, then test playback with `ffplay OUTPUT_DIR/master.m3u8` or serve locally with `python3 -m http.server 8000` and load it in a browser.

Two things to confirm before you run this:
1. **The input path/filename** — I don't have it, so swap `INPUT_VIDEO.mov` for your actual file.
2. **Codec build check** — since you're on macOS, this is a good candidate for `-c:v h264_videotoolbox` instead of `libx264` for 2-3x faster encoding on an 8GB source; run `ffmpeg -encoders | grep videotoolbox` first to confirm your build has it, since software `libx264` at this size could take a long time even on `-preset fast`.
