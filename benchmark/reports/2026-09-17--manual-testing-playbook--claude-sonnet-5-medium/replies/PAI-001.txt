Turn 2
Prompt: It is a hero photo, 6MB PNG, and I want it light for the homepage.

Reply:
Hero images benefit most from two things: capping the pixel dimensions to what a browser actually displays, and switching off PNG (lossless, heavy) to a compressed web format.

**Recommended approach: WebP at quality 85**, since it typically cuts file size 60-80% versus PNG while keeping good visual quality. Fallback to JPEG quality 80 if your hosting/CDN needs universal support (WebP is well-supported now, but check your stack).

**Run this:**

```bash
# Check the build supports WebP first
ffmpeg -encoders | grep webp

# Resize + convert to WebP (adjust 1920 to your actual hero display width)
ffmpeg -i input.png -vf "scale=1920:-1" -c:v libwebp -quality 85 export/001\ -\ hero-webp/hero.webp
```

If you need a universal JPEG fallback too:

```bash
ffmpeg -i input.png -vf "scale=1920:-1" -q:v 5 export/001\ -\ hero-webp/hero.jpg
```

- **Result lands in:** `export/001 - hero-webp/` (both files if you run both commands)
- **Check this:** run `ffprobe export/001\ -\ hero-webp/hero.webp` to confirm output dimensions and codec, then check the file size — a 6MB hero PNG at 1920px WebP typically lands in the 150-400KB range depending on image complexity. Do a visual check at 100% zoom for banding or artifacts before shipping.

A couple of notes: if the original PNG is much larger than 1920px wide (say a 4K source), the resize alone often accounts for most of the savings — worth confirming your actual display width first. If the image has transparency you need to keep, WebP preserves alpha; JPEG does not.
