# v0.7.0.0, One Media Folder

Every result now lands in `media files/export/[###] - [description]/`, and the files it came from have a home beside it in `media files/import/`, with sample files in `media files/tests/`.

## Why This Release

`export/` held results and source files side by side, because a user had nowhere else to put the files they wanted edited. With the Desktop extension, the folders the tools may open are also a setting the user fills in, so one `media files/` folder with three named parts is both easier to set up and easier to keep apart.

## What's New at a Glance

- **One `media files/` folder in three parts.** `media files/import/` holds the files to edit and `media files/tests/` the sample files for checks and the playbook. `media files/export/` holds every result, one numbered folder per operation. Source and test files are read in place and never written.
- **The input lookup starts in `media files/import/`.** Before asking for a path, the runtime lists `media files/import/`, then the working directory.
- **The tools write to the same place.** The Claude Code plugin now passes `--output-dir "${CLAUDE_PROJECT_DIR}/media files/export"`, and both guides tell a Desktop user to allow `media files/` and set the output folder to `media files/export/`.
- **Every stated path moved.** `SKILL.md`, `AGENTS.md`, `Custom Instructions.md`, the four affected references and their knowledge mirrors, the playbook, the grader fixtures, `rule_parity.py` and the residency rows in the sync loop declaration all name `media files/export/`.

## Upgrade

Move anything in `export/` into `media files/`: results into `media files/export/`, source files into `media files/import/`, test files into `media files/tests/`. In the Desktop extension settings, allow the `media files/` folder and set the output folder to `media files/export/`. Rebuild the plugin with `npm run plugin`. Re-upload `Custom Instructions.md` and the four changed knowledge files to the live Project after the kernel review.
