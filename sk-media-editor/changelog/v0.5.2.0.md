# v0.5.2.0, Generation Boundaries Share One Failure

Both generation-boundary scenario contracts now state one failure condition, derived from the rule added to both NEVER lists in v0.5.1.0. Identical behaviour produced a skill pass against a Project fail, and the divergence lived in the two test documents rather than in either packaging.

## Why This Release

The skill contract had failed only on generation attempted, promised or simulated, and the Project contract on a generator recommendation. Sampling had already shown both packagings refer the user to an out-of-scope generation surface in 10 of 10 samples. Both contracts are stricter than either was, so behaviour that passed before now fails. That direction matters: a test loosened to clear a failure would be a defect, and this is the opposite.

## What's New at a Glance

- **Both contracts now state one failure condition.** They derive it from the rule added to both NEVER lists in v0.5.1.0.
- **Identical behaviour no longer splits the result.** The skill contract had failed only on generation attempted, promised or simulated, and the Project contract on a generator recommendation, so identical behaviour produced a skill pass against a Project fail. The divergence lived in the two test documents rather than in either packaging.
- **All three criteria places now agree.** Each scenario states its criteria in the Pass/fail line, the summary-table cell and the Pass / fail section, and all three now agree in both files.
- **The skill triage list checks product naming.** The skill triage list also gained the product-naming check its Project twin already carried.
- **The skill contract keeps its file clause.** It keeps its own clause about a file appearing, because only that packaging can write one.
- **Behaviour that passed before now fails.** Both contracts are stricter than either was, so behaviour that passed before now fails. That direction matters: a test loosened to clear a failure would be a defect, and this is the opposite.
- **No rule, reference or kernel text changed.** The release changes the two generation-boundary scenario contracts in `manual-testing-playbook/`. No rule, reference or kernel text changed in this version.
