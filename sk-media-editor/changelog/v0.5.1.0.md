# v0.5.1.0, Find the Input and Name No Generator

Across sixteen recovered skill transcripts the split was exact: every run that enumerated its working directory found the seeded fixture and produced the export, and every run that did not asked the user for a path while the named file sat beside it. Both packagings pointed the user at an out-of-scope generation surface in 10 of 10 samples, and two skill samples named products outright. The intake rule now looks for the input first, and the generation rules now draw an explicit line.

## What's New at a Glance

- **The skill lists the working directory before it asks for a path.** Nothing in the skill or the claude.ai Project told a runtime to look for its input, and the intake rule asked one comprehensive question covering media type, file, goal and output and said nothing about the working directory. `AGENTS.md` now says to list the working directory before asking for a path and to ask only when nothing there matches or more than one does.
- **This lookup rule sits in `AGENTS.md` rather than `SKILL.md`.** `AGENTS.md` is passed as the skill's system prompt, so the rule is in context by construction rather than by the runtime choosing to open a reference.
- **The lookup rule is skill-side only.** A claude.ai Project has no working directory and legitimately hands back a command with the input and output paths the user sets.
- **Naming a generation product is the same breach as generating.** The NEVER rules in `SKILL.md` and `Custom Instructions.md` permit saying that generating new media falls outside this scope and treat naming a generation product or giving any step toward generating as that same breach. Neither side had said whether naming a generation tool was permitted, and `references/media-framework.md` positively invites offering a next step.
- **The generation rule is deliberately stricter than either boundary scenario currently tests.** The skill scenario fails only on generation attempted, promised or simulated, and the Project scenario fails on a generator recommendation, so identical behaviour passed the skill and failed the Project. Both contracts are now out of step with the rule and are owed an alignment to it, not the reverse.
