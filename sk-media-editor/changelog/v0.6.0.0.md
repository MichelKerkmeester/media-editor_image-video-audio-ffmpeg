# v0.6.0.0, Tools First, Then ffmpeg, Then Advice

Every operation now takes the first route that is available: the Media Editor tools when they are connected, then locally installed ffmpeg, then advice with the exact command when neither can run.

## Why This Release

Until now the Media Editor drove one tool surface. The skill needed ffmpeg on the path and stopped without it, and the claude.ai Project could only hand back a command. The new Media Editor MCP server in `mcp server/` carries its own pinned ffmpeg and installs in one step, as a Claude Desktop extension or as a Claude Code plugin, so a user without a terminal can have their media edited. Both packagings had to learn to use it without losing the honest advice path for claude.ai on the web.

## What's New at a Glance

- **One route order in every packaging.** `SKILL.md`, `AGENTS.md` and `Custom Instructions.md` state the same order in the same sentence, and the five operational references carry it in their precondition lines.
- **A tool check replaces the ffmpeg check.** With the tools connected, `media_health` reports the ffmpeg the server found, its encoders and filters and the allowed folders. When it names `media_setup_ffmpeg`, the user sees the pinned download and agrees to it before anything is fetched. A tool that cannot reach the file's folder asks the user to allow that folder, and one missing a capability falls back to local ffmpeg or to advice.
- **The Project can run tools in Claude Desktop.** With the extension installed, a Project reply leads with the tool that ran and the folder it returned, and its attestation line says `execution = tool ran`. Without the tools, the no-execution attestation and every advisory rule are unchanged.
- **Advice replaces the hard stop.** A skill runtime with neither route gives the exact command, says plainly that nothing ran and points to the extension, the plugin or an ffmpeg install.
- **The playbook grows to nineteen scenarios.** `SRO-001` and `PRO-001` test the tools route in Claude Code and Claude Desktop with the same prompt, `SRO-002` tests the fallback to installed ffmpeg, and `STV-001`, renamed Missing FFmpeg advice, now expects advice rather than a stop.
- **Gates moved with the wording.** `rule_parity.py` pins the five new precondition sentences, the residency rows in the sync loop declaration were resynced, and `twin_divergence.py` declares the new twin pair.

## Upgrade

Install the Claude Desktop extension or the Claude Code plugin to use the tools, as `INSTALL-GUIDE.md` describes. Nothing changes for a runtime that uses installed ffmpeg. Re-upload `Custom Instructions.md` and the five changed knowledge files to the live Project after the kernel review.
