# v1.1.1.0, Kernel and README Match the Skill

`claude project/Custom Instructions.md` moves from kernel v1.0.0 to v1.0.1 and closes four contract gaps against `SKILL.md` v1.1.0. `claude project/README.md` closes three matching operational gaps in the same pass. `SKILL.md` itself is unchanged, since every contract detail these fixes require already existed at source, so only the derived kernel and README needed to catch up.

## What's New at a Glance

- **The Guidance Block names a verification command per mode.** Section 7's Tool field now spells out `list_images` for Imagician, `health_check` for Video-Audio and `ffmpeg -version` for FFmpeg, matching the Tool Verification Gate in `SKILL.md`. It used to read `Imagician, Video-Audio or FFmpeg, plus a verification command or check` and named no command.
- **Feature Realism states the two hard limits.** Section 2 now states over 100MB for MCP operations and over 5GB for HLS, matching NEVER rule 3 in `SKILL.md`. It used to flag limits by category only.
- **Explicit command tokens override natural-language scoring.** Section 5's Smart Routing Logic now states that explicit command tokens override natural-language mode scoring, matching the Routing Checks in `SKILL.md`. It used to open straight into the routing table with no precedence statement.
- **The attestation footer states that execution, verification and save did not occur.** Section 7's wording now matches the advisory-only attestation contract. It used to carry only `execution = advisory-only`.
- **The Set Up smoke test adds `$repair` and `$interactive`.** Those modes join the existing four command tests plus the ambiguous-request case. The test used to exercise four of six modes.
- **Guidance Block validation requires all six fields.** It now requires Deliverable, Tool, Recipe, Settings, Expected result and Attestation, plus the two-to-three sentence post-block instructions. It used to check only the attestation footer and the advisory-only statement.
- **Filenames follow the version-bump-and-rename rule.** The unconditional "keep filenames unchanged" rule is replaced with the version-bump-and-rename rule that already governs the Change Checklist.
- **A drift check must pass before release.** A final Change Checklist step now requires every `SYNC.md` section 7 drift check to pass before release.
- **The SYNC pin matches the kernel.** `SYNC.md` now pins Custom Instructions at 1.0.1, where it used to pin 1.0.0.
