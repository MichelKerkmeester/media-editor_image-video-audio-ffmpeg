# v1.0.0.0, Both Runtimes Share One Brain

The Media Editor's dual-runtime packaging lands for the first time. A command-line `skill/` folder pairs with a `claude project/` mirror for chat. `SKILL.md` becomes the one brain. It replaces an older routing model where a separate always-loaded document carried that role.

The system's first tracked copy predates this release. On 2026-04-10 it lived at `MCP Agents/Media Editor/`. That copy held only the `knowledge base/` and `mcp servers/` pairing. It had no `skill/` folder and no `claude project/` folder. A separate restructuring pass deleted that grouped-path version outright on 2026-05-21. The 2026-06-15 commit is the first to add the content back. The new tree sits at the flat `Media Editor/` path. The files already use the dual-runtime shape.

`SKILL.md` carries version 1.0.0 in its frontmatter, the metadata block at the top of the file. That is the first system-level version number the Media Editor has had. Before 2026-06-15 the architecture used only per-document versions. The system had no single release number. Those document versions were Prompt v0.240, MEDIA Framework v0.233 and Interactive Intelligence v0.220. The two MCP integration specs were at v0.211 and v0.212. HLS was at v0.110. Changelog records for this system begin here. Media rules, tool bindings and the export protocol carry over unchanged from the prior architecture.

## Why This Release

Routing lived in a separate always-loaded document. The system had per-document versions and no single release number. This release replaces that routing model with `SKILL.md`. It gives the Media Editor its first system version and the first changelog record.

## What's New at a Glance

- **Dual-runtime packaging pairs a skill with a chat mirror.** The command line reads `skill/`. Chat reads the `claude project/` mirror.
- **SKILL.md becomes the one routing brain.** It takes the role of the always-loaded system prompt. The command set stays the same.
- **The old knowledge base stays on disk.** The folder is demoted and still holds the retired prompt for comparison. Neither runtime loads that prompt.
- **The two MCP servers build differently.** Imagician ships a compiled bundle. The video and audio server clones its source at build time.
- **A human voice re-freeze lands the same morning.** The Human Voice mirror moves to the sk-doc reference template and the chat README is refreshed. The skill version does not change.
- **This is the first version for the system as a whole.** `SKILL.md` carries 1.0.0. Changelog records begin with this release.
- **Media rules carry over unchanged.** Tool bindings and the export protocol stay as they were in the prior architecture.

## The Skill and the Chat Mirror

#### SKILL.md Becomes the One Brain

`skill/` is the source of truth for the command line. It holds `SKILL.md` and `assets/hls_video_conversion.md`. It also holds five files in `references/`. Those files are `human_voice_rules.md`, `interactive_intelligence.md`, `media_framework.md`, `mcp_imagician.md` and `mcp_video_audio.md`. The asset file and the five reference files are underscore-named.

**Breaking:** Routing moves out of `Media Editor - System - Prompt - v0.240.md` and into `SKILL.md`. The prior AGENTS.md pointed to the old file as "the System Prompt". It did not embed the routing itself.

The commands stay the set the old system prompt already routed. They are `$image`, `$video`, `$audio`, `$hls`, `$repair` and `$interactive`.

&nbsp;

#### Chat Gets a Matching Mirror

`claude project/` is the mirror for chat. It holds `Custom Instructions.md` and a `README.md`. It also holds a `knowledge/` folder with seven files. One of them is the first `Media Editor - System - Skill - v1.0.0.md`.

## The Old Knowledge Base

#### The Retired Prompt Stays for Comparison

The `knowledge base/` folder from before this packaging is not deleted. It is only demoted. It keeps the `integrations/`, `reference/` and `system/` subfolders. It keeps six files. One of them is `Media Editor - System - Prompt - v0.240.md`. That file has no match among the seven files in `claude project/knowledge/`. It is the retired always-loaded system prompt. It stays for manual comparison. Neither runtime wires it in.

## Two Ways to Build the Tools

#### Imagician Ships a Compiled Bundle

The two MCP servers are packaged differently from the start. Both build strategies are present from the system's earliest tracked commit under the new `Media Editor/` path. `mcp servers/imagician/` includes a prebuilt `dist/index.js` beside its own `package.json`. Its Dockerfile installs dependencies and copies the compiled bundle directly.

&nbsp;

#### Video and Audio Clone on Build

`mcp servers/video-audio/` carries no `dist/` folder and no `package.json`. Its Dockerfile clones `misbahsy/video-audio-mcp` from GitHub at build time. It installs Python requirements from that clone. The tool layer is the same. The build strategies differ.

## The Human Voice Mirror

#### The Mirror Follows the Template

A second commit later that same morning converts the Human Voice mirror to the sk-doc reference template. It also refreshes `claude project/README.md`. The commit touches only those two files. No skill version bump accompanies it. This human voice re-freeze produces the `f8980baed64d` checksum lineage. Later README manifests still carry that lineage for the file.

## Upgrade Notes

- **Adopt.** Use `skill/SKILL.md` as the routing brain on the command line. Use `claude project/` for chat.
- **Repoint.** Open `SKILL.md` for routing instead of `Media Editor - System - Prompt - v0.240.md`. Find the files under `Media Editor/` instead of `MCP Agents/Media Editor/`.
- **Drop.** The always-loaded system prompt is no longer wired into either runtime. The file stays in `knowledge base/` for manual comparison only.
