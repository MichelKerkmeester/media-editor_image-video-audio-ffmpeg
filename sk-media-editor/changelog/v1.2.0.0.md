# v1.2.0.0, Down MCP Servers Fall Back to FFmpeg

The Media Editor learns to fall back. When the Imagician MCP server is down for an image operation, or the Video-Audio MCP server is down for a video or audio operation, the CLI runtime now drives Terminal FFmpeg directly for that operation instead of stopping. The fallback still requires FFmpeg to be available. When the MCP server is down and FFmpeg is also unavailable, the operation blocks and the response says so plainly. That case stays a real stop rather than a silent degrade.

HLS is untouched and still runs on Terminal FFmpeg alone with no fallback. `SKILL.md` moves from 1.1.0 to 1.2.0. The advisory kernel `Custom Instructions.md` moves from 1.0.1 to 1.1.0, aligned to Skill 1.2.0. The HLS asset moves from 0.110 to 0.111.

The release also corrects a fallback statement that ran the wrong direction. That statement named the Video-Audio MCP server as a fallback for FFmpeg. The runtime need is the reverse.

## Why This Release

The Tool Verification Gate blocked unconditionally on the one tool tied to a mode. Image operations, video operations and audio operations now prefer their MCP server and continue on Terminal FFmpeg when that server is down. The operation stops only when the MCP server and FFmpeg are both unavailable.

A fallback statement ran the wrong direction. It named the Video-Audio MCP server as a fallback for FFmpeg, while the runtime need is the reverse. This release corrects that statement and uses the same direction in the skill, the advisory kernel and the other surfaces.

## Routing When a Server Is Down

#### Work Continues on Terminal FFmpeg

The Tool Verification Gate in `SKILL.md` moves from unconditional blocking to an MCP-first path with a Terminal FFmpeg fallback. Image operations prefer the Imagician MCP server and fall back to Terminal FFmpeg. Video and audio operations prefer the Video-Audio MCP server and fall back to Terminal FFmpeg. The old gate hardcoded one tool per mode and used a blocking check.

The gate blocks only when the MCP server and FFmpeg are both unavailable. The response says so plainly. MEDIA Flow STEP 2, the Operating Modes table, the ALWAYS, NEVER and ESCALATE rules and the Success Criteria gates all state this same direction.

&nbsp;

#### The Statement Points the Right Way

A fallback statement ran the wrong direction. It named the Video-Audio MCP server as a fallback for FFmpeg. The runtime need is the reverse, so Terminal FFmpeg is the fallback when the MCP server is down.

&nbsp;

#### HLS Stays on FFmpeg Alone

HLS is untouched and still runs on Terminal FFmpeg alone with no fallback. The HLS asset moves from 0.110 to 0.111. It no longer casts Terminal FFmpeg as HLS-only. It records that FFmpeg is also the fallback for single-format conversions and editing when the MCP server is down.

---

## What the Fallback Covers

#### Core Edits Map to FFmpeg

A new Fallback Coverage subsection in `SKILL.md` Integration Points states what Terminal FFmpeg genuinely substitutes for and what it does not, drawn from the real Imagician and Video-Audio tool surfaces rather than an assumed parity. The fallback covers format conversion, resize, crop, compress, rotate and flip for images. It also covers trim, concatenate, speed, resolution, aspect ratio, codec, bitrate, frame rate and audio extraction for video and audio. Video-Audio is itself an FFmpeg wrapper, so its core operations map directly to FFmpeg command lines.

&nbsp;

#### The Gap Is Packaging Convenience

The subsection names what does not reach parity. Imagician single-call batch arrays become a scripted FFmpeg loop. Sharp quality presets do not map to FFmpeg quality numbers exactly. EXIF orientation auto-correction needs an explicit transpose. The Video-Audio convenience tools for silence removal, named transitions, overlays, subtitles and b-roll need hand-built filtergraphs.

No listed operation is impossible in FFmpeg. The gap is packaging convenience and preset calibration, not raw capability.

---

## The Answer Names the Path

#### Fallback Output Is Never MCP Output

A new house rule requires every response that ran through the fallback to state plainly that it ran via Terminal FFmpeg rather than the named MCP server. The response never presents an FFmpeg result as MCP output. On the skill side the rule lands in the Tool Verification Gate, in a new ALWAYS entry and in the NEVER list. On the advisory side it lands as Critical Rule 9, in the Delivery Protocol post-block instruction and in the Quality Checklist.
