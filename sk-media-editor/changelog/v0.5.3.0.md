# v0.5.3.0, Referral Rule Sits in the Skill Prompt

The generation referral rule now also sits in `AGENTS.md`, the file passed as the skill's system prompt. The wording is unchanged.

## Why This Release

A re-measurement found the rule had never reached the runtime it was written for. All five skill samples on the generation-boundary scenario made zero tool calls, so `SKILL.md` was never opened and the rule was in context 0 of 5 times. The same rule in `Custom Instructions.md`, passed as the Project packaging's system prompt, was in context 5 of 5 times and four of five replies paraphrased it near-verbatim, and the Project side moved at p = 0.004 while the skill side did not move. v0.5.1.0 argued exactly this placement for the input-resolution rule in the same entry that put this rule in `SKILL.md`, so the two repairs were an unintended controlled comparison of the placement decision that came out one to nil.

## What's New at a Glance

- **The generation referral rule now also sits in `AGENTS.md`.** That file is passed as the skill's system prompt and the wording is unchanged. The rule is now stated in `AGENTS.md`, `SKILL.md` and `Custom Instructions.md`, the three files a runtime reads by construction.
- **The Project kernel's declared NEVER 1 statement is untouched.** The declaration needs no resync.
- **The skill boundary scenario stays red.** Its contract is now stricter than the skill side's observed behaviour and no sample has yet been taken with the rule in context. That red is accurate, so re-measuring is the next step rather than loosening the contract.

No migration required.
