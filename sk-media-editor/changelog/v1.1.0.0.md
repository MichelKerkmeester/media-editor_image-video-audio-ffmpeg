# v1.1.0.0, One Question First and the media-editor Command

The Media Editor now asks one question before it writes anything, with a proposed name for every result and, for several files, a choice of where they go. In Claude Code the skill runs the tools through the `media-editor` command, and the plugin ships that command in place of an MCP server.

## Why This Release

A clear request such as "convert these four PNGs to webp under 100kb" went straight to work. Four separate calls left four results under the imported names, sometimes spread across four numbered folders, and the user never had a say in either.

In Claude Code the plugin registered an MCP server, so the skill depended on a server process that had to start and stay connected. The same tools run fine as a command in the Bash tool, which Claude Code already has. Asked for a conversion, Claude Code also tended to skip the skill and run `cwebp` or `ffmpeg` itself, writing files under the original names without asking.

## What's New at a Glance

- **One question before the first write.** Every surface asks once, even when the request is clear, with a proposed name for every output file. Two or more inputs from one request also get the choice between the export folder and one numbered folder.
- **`targetFolder`.** The separate calls of one request share the folder the first call made.
- **`maxBytes` on `image_convert`.** A size cap for `jpeg`, `webp` and `avif` that lowers quality until the file fits and never resizes.
- **The `media-editor` command.** `list`, `describe`, `health` and every tool by name, with arguments as JSON from `--args`, `--args-file` or standard input.
- **The plugin ships the command.** It carries `bin/media-editor` and registers no MCP server.
- **The skill triggers on conversions.** Its description now says when to use it and that it replaces running `cwebp`, `ffmpeg`, `sips` or ImageMagick directly.
- **Fewer second questions.** A reply that confirms the proposal settles every point it leaves out, and a request whose names and place are settled goes straight to work.
- **`nextStep` on `media_health`.** A missing ffmpeg names the setup tool, and the skill runs it before asking anything.

## Runtime

#### Shared Folders and Size Caps

Every writing tool except `video_hls_ladder` takes `targetFolder`, an existing numbered folder directly inside the output folder, named exactly as an earlier call returned it. The first call of a batch passes `subfolder` `true` and every later call passes `targetFolder`. A missing folder, a name without the `NNN - ` prefix, a path or a symlink is refused, and a taken name inside that folder moves on to `-2`. `image_convert` takes `maxBytes`, where 1 KB is 1,000 bytes. When even quality 1 is too large it writes nothing and returns `INVALID_INPUT` with `smallestBytes`.

&nbsp;

#### The media-editor Command

`dist/cli.js` runs any registered tool from a terminal without an MCP client. Paths inside the JSON must be absolute. The command prints the tool's JSON result and exits 0 on success, 1 on a tool error, 2 on a usage error and 3 when it cannot start. The allowed folder defaults to the working folder and results go to `media files/export` inside it.

&nbsp;

#### A Plugin Without a Server

`npm run plugin` builds a plugin that holds `bin/media-editor`, the bundled runtime and the skill. The build refuses a manifest that declares `mcpServers`. The folder that held the runtime is now `runtime/`.

&nbsp;

#### A Health Check That Names the Fix

`media_health` returns `nextStep`. It names `media_setup_ffmpeg` when ffmpeg or ffprobe is missing and is `null` otherwise, so the command's JSON output carries the next step that the MCP text already gave.

## Skill and Project

#### The Naming and Placement Gate

`SKILL.md`, `AGENTS.md`, the kernel and `references/interactive-intelligence.md` ask one question before the first writing call. Several files means per request, not per call. `media_rename` covers renaming afterwards only. ESCALATE 1 no longer limits the question to ambiguous requests. The image and video references document `targetFolder` and `maxBytes`, and each Knowledge mirror took the same text byte for byte.

&nbsp;

#### Command First in Claude Code

The skill reaches the tools through `media-editor` in the Bash tool, then hand-written ffmpeg only when the command is unavailable, then advice. Other encoders are never used. The new skill-only `references/cli.md` covers the command, its exit codes and a worked four-file batch. The router contract's `choose_route` gained `media_cli_available()` and a `cli` route ahead of `tools`, and the kernel's Router Code took the same line with the Project binding it false. The seven mirrored references now say the tools are available rather than connected, so one text reads true on every surface.

&nbsp;

#### A Description That Triggers

The frontmatter `description` leads with when to use the skill, and a new `when_to_use` names the operations, the example "convert these PNGs to webp" and the encoders the skill replaces. ALWAYS 1 says the same.

&nbsp;

#### Rules From the Playbook Run

Every scenario ran at Sonnet 5.5 medium until each passed for both graders, and each failure got its fix at its cause.

- An answer that confirms the proposal and skips a point accepts the recommendation stated for that point. When every output has a confirmed name and place, the reply settles the rest with smart defaults, names them and writes.
- Unknown media still gets a working name built from the stated purpose, written into the question.
- An oversized request leads with its cost in time and disk and offers the lighter path first.
- A reply that notices a mistake in a command it gave repeats the whole corrected command.
- In the Project, Repair Mode answers at once with the diagnosis and repair commands, input paths are built from the allowed folders and the given file name, and the first no-tools reply offers once to walk through installing the extension.
- On the ffmpeg route, a naming preview renders in the system temp folder, output is written with `-n`, and trial encodes for a size target run in the temp folder.
