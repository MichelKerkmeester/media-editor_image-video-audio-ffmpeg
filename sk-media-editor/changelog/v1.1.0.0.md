# v1.1.0.0, The Skill Moves Off MCP and Asks Before It Writes

In Claude Code the Media Editor skill no longer depends on an MCP server, the protocol that connects a separate tool process to Claude. It runs the same 40 tools through `media-editor`, a command the plugin ships and Claude calls from its Bash tool, so nothing has to start or stay connected before the first edit. The Claude Desktop extension keeps its MCP server, because a Project has no terminal to run a command in.

Every surface also asks once before it writes. The first reply to a request that saves a file proposes a readable name for each result and, for several files, the choice between the export folder and one numbered folder. Four conversions now land under four names the user confirmed, in one place.

The rules around that question were then tested on every scenario in the manual testing playbook until each passed for two independent graders. The result is fewer second questions, a missing ffmpeg that fixes itself before anything is asked and replies that never overwrite a file.

## Why This Release

**The skill hung on a server.** The plugin registered an MCP server that had to start and stay connected, and when it did not, the skill fell back to hand-written ffmpeg. Asked for a conversion, Claude Code also tended to skip the skill and run `cwebp` or `ffmpeg` itself.

**A clear request went straight to work.** "Convert these four PNGs to webp under 100kb" left four results under their imported names, sometimes spread across four numbered folders, and the user never had a say in either.

## What's New at a Glance

- **The skill runs on the `media-editor` command.** Every tool is one command away, with its arguments as JSON and its result printed as JSON.
- **The plugin ships the command, not a server.** It carries `bin/media-editor` and registers no MCP server.
- **Claude Code reaches for the skill.** A conversion request now loads it instead of running `cwebp`, `sips` or ImageMagick directly.
- **One question before the first write.** It proposes a name for every result and, for several files, one place to put them.
- **Fewer follow-up questions.** A confirmed proposal settles every point it leaves out, and a request with its names and place settled goes straight to work.
- **A batch shares one folder.** The separate calls of one request write into the folder the first call made.
- **A size cap on conversions.** `image_convert` takes `maxBytes` and lowers quality until the file fits, never resizing it.
- **A missing ffmpeg names its own fix.** The health check returns the setup step, and the skill runs it before asking anything.

## Claude Code

#### The Skill Runs on a Command, Not a Server

`media-editor` exposes `list`, `describe`, `health` and every tool by name, with arguments from `--args`, `--args-file` or standard input. It prints the tool's JSON result and exits 0 on success, 1 on a tool error, 2 on a usage error and 3 when it cannot start. Paths inside the JSON are absolute, and results go to `media files/export` in the project folder.

The skill's route order is now the command first, then hand-written ffmpeg only when the command is unavailable, then advice. Other encoders are never used. The new `references/cli.md` covers the command, its exit codes and a worked four-file batch.

&nbsp;

#### The Plugin Ships the Command

**Breaking:** the plugin no longer registers an MCP server, so Claude Code lists no Media Editor tools. The skill runs `media-editor` in the Bash tool instead, and the build refuses a manifest that declares `mcpServers`. Because claude.ai and Cowork do not install a plugin that carries a `bin/` folder, the plugin now reaches Claude Code only. A Project uses the Desktop extension.

&nbsp;

#### A Description That Triggers the Skill

The skill's description now leads with when to use it, and a new `when_to_use` names the operations, the example "convert these PNGs to webp" and the encoders the skill replaces. A live Claude Code run had skipped the skill and written files with `cwebp`, under their original names and without asking.

## Naming and Placement

#### One Question Before the First Write

`SKILL.md`, `AGENTS.md`, the Project kernel and the interactive flow all ask one question before the first writing call, even when the request is clear. Several files means several from one request, not from one call, so a batch of single-file calls still gets one folder choice. `media_rename` now covers renaming afterwards only.

&nbsp;

#### Questions That Settle Themselves

An answer that confirms the proposal and skips a point accepts the recommendation stated for that point, and the reply says so. When every result already has a confirmed name and place, the reply settles the rest with smart defaults, names them and writes. Media the reply cannot see yet still gets a working name built from the purpose the request states, written into the question rather than promised for later.

&nbsp;

#### One Folder for a Batch, a Cap for Size

Every writing tool except `video_hls_ladder` takes `targetFolder`, an existing numbered folder inside the export folder, named exactly as an earlier call returned it. The first call of a batch passes `subfolder: true` and every later call passes `targetFolder`. A taken name inside that folder moves on to `-2`. On `image_convert`, `maxBytes` caps a `jpeg`, `webp` or `avif` file, where 1 KB is 1,000 bytes, and when even quality 1 is too large it writes nothing and reports the smallest size it reached.

## Safer Replies

#### A Missing ffmpeg Fixes Itself First

`media_health` returns `nextStep`, which names `media_setup_ffmpeg` when ffmpeg or ffprobe is missing and is empty otherwise. The skill runs that setup in the same turn, so its plan is part of the one question rather than a second one.

&nbsp;

#### Hand-Written ffmpeg Never Overwrites

On the ffmpeg route, a preview for naming renders in the system temp folder rather than under `media files/`. Output is written with `-n`, so an existing file is never replaced, and trial encodes for a size target run in the temp folder until the confirmed name is written once.

&nbsp;

#### Project Answers Lead With What Works

In a Project, Repair Mode answers at once with the diagnosis and repair commands, and a question about the symptom follows them rather than replacing them. Input paths are built from the allowed folders and the file name the user gave, because the tools cannot list a folder. An oversized request leads with its cost in time and disk and offers the lighter path first. The first reply without tools offers once to walk through installing the extension, and a reply that notices a mistake in a command repeats the whole corrected command.

## Upgrade Notes

- Re-upload `Custom Instructions.md` and all seven Knowledge files to the live Project
- Install the Desktop extension from this release's `.mcpb` file for your computer
- Rebuild the plugin with `npm run bundle` and `npm run plugin`, then reinstall it. Claude Code shows no Media Editor tools afterwards, because the skill runs `media-editor` in the Bash tool
- Expect the first reply to a request that writes a file to ask one question with the proposed names and, for several files, the folder choice
