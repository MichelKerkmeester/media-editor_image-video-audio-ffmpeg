# v0.2.0.0, The Skill Folder Settles Its Name

media-editor 0.2.0.0 settles the skill folder on `sk-media-editor/`. The `SKILL.md` frontmatter version moves from 0.1.0 to 0.2.0. The frontmatter `name: media-editor` stays the name you use to invoke the skill. Guide and reference filenames use hyphens. The new skill README documents Repair Mode.

Git history records the tracked rename from `skill/SKILL.md` straight to `mcp-media-editor/SKILL.md`. The intermediate `sk-media-editor/` name lived in the working tree and never reached its own commit. On 2026-07-17 the folder was `mcp-media-editor/`. Later that day it moved back to `sk-media-editor/`.

This release also records the unversioned documentation pass of 2026-07-13. That pass includes the export protocol's first worked example in this system's own folder.

## Why This Release

This release aligns packaging and structure with the nine-system alignment wave. It records the folder renames, the hyphenated guide names and the first structural rewrite of `SKILL.md` since the June baseline. It also closes out the 2026-07-13 pass, which restructured `claude project/Custom Instructions.md` and `claude project/README.md` for clearer routing and delivery language while the skill pin stayed at 0.1.0.

On 2026-07-17 the owner chose the name `mcp-media-editor/` because this system fronts MCP servers rather than authoring documents outright. Later the same day the fleet standardized every skill folder on the `sk-` prefix. This folder returned to `sk-media-editor/`. MCP tool bindings, media rules and mode canon are untouched.

## Folder Names

#### The Live Folder Is sk-media-editor

During the nine-system alignment wave the skill folder was renamed from `skill/` to `sk-media-editor/` and then to `mcp-media-editor/` on 2026-07-17. The owner chose `mcp-media-editor/` because this system fronts MCP servers rather than authoring documents outright. Git history records that hop as the tracked rename from `skill/SKILL.md` straight to `mcp-media-editor/SKILL.md`. The intermediate `sk-media-editor/` name lived in the working tree and never reached its own commit.

Later the same day the fleet standardized every skill folder on the `sk-` prefix. This folder moved from `mcp-media-editor/` back to `sk-media-editor/`. The changelog keeps the name each event actually used. The frontmatter `name: media-editor` stayed unchanged through all three names.

&nbsp;

#### Retired Paths Were Repointed

The rename left `knowledge base/` and `mcp servers/` in place. Both were searched for stale references to the old skill path, and those references were repointed. While the folder was `mcp-media-editor/`, a check across the folder tree found no remaining pointers to the retired `skill/`, `sk-media-editor/` or `INSTALL_GUIDE.md` names.

After the folder moved back to `sk-media-editor/`, references were swept again. The knowledge mirrors were checked byte for byte again. The manifest hash rows were recomputed.

`SYNC.md` was a flat note. It is now a manifest with eight numbered sections following the sk-doc section standard, from Overview through Related Documents.

## The Skill Text

#### SKILL.md Moves to Version 0.2.0

`SKILL.md` was rewritten to the create-skill standard. This is its first structural rewrite since the June baseline. The frontmatter version moves from 0.1.0 to 0.2.0. The frontmatter `name: media-editor` stays the invocation contract, the name you use to invoke the skill, across both folder renames.

&nbsp;

#### Repeated Sections Are Collapsed

Three duplications collapse into one telling. The old Section 2 phase-detection diagram is removed. It repeated the same six-step sequence the Section 3 MEDIA Flow already states. The diagram numbered the steps as `STEP 0-2` plus `Phase 1-3`. MEDIA Flow numbers them as `STEP 1-6`.

Section 7 folds its old Tool Layer and Knowledge Base Dependencies subsections into one paragraph. That paragraph points back to Section 3 and Section 5 instead of repeating them. The standalone Section 8, References And Related Resources, disappears into Section 5. The document goes from eight top-level sections to seven.

&nbsp;

#### Reference Files Use Hyphens

Six reference and asset filenames convert from underscore to hyphen, matching the folder-wide hyphenation. `media_framework.md` becomes `media-framework.md`, `human_voice_rules.md` becomes `human-voice-rules.md`, `mcp_imagician.md` becomes `mcp-imagician.md`, `mcp_video_audio.md` becomes `mcp-video-audio.md`, `hls_video_conversion.md` becomes `hls-video-conversion.md` and `interactive_intelligence.md` becomes `interactive-intelligence.md`.

&nbsp;

#### The Voice Rules Stay in the Skill

`human-voice-rules.md` is a relative symlink and an always-loaded resource. The guard now uses that file's absolute path. Resolving the symlink would follow the relative link out of the skill root. The guard would then fail for this always-loaded resource.

&nbsp;

#### The Phantom Brand Link Is Gone

The old Resource Domains line named a `brand` global. This skill never actually loads that global. A follow-up canon fix removed the mention from `SKILL.md`. The line now names only `human-voice-rules`.

## Mirrors and Canon

#### Knowledge Mirrors Match the Sources

All seven `claude project/knowledge/` mirrors are byte-identical to their `mcp-media-editor/` sources, meaning each mirror file has the same bytes as its source. The check was file by file rather than only by count. The eight checksum rows in `claude project/README.md`, the seven mirrors plus Custom Instructions, were recomputed against the final bytes.

&nbsp;

#### Two Canon Mismatches Were Fixed

The closing drift audit confirmed and fixed two findings. One was a stale kernel section count. The other was a Repair-row tool binding that contradicted the auto-detect canon. A follow-up canon fix removed the phantom `brand` symlink mention from `SKILL.md`.
