# Media Editor CLI, Skill Split and Batch Naming Design

Deepseek lineage synthesis, five iterations, 2026-10-04.

## 1. Executive Summary

Build one dispatcher and two thin adapters. Extract the tool dispatch from the MCP registry into a transport-neutral module, expose it through a separate CLI entry with real exit codes and signal cleanup, and keep the MCP host contract unchanged. Ship the CLI inside the existing per-platform bundle, put a bare `media-editor` command on the Claude Code Bash PATH through a plugin `bin/` shim, and give other terminal agents a `bin` entry in the package. Make the skill route the CLI first, hand-written ffmpeg second and advice last, while the Claude Project keeps the Desktop extension and MCP. Harden the batch flow with one question before the first writing call, a `targetFolder` field so the separate calls of one request share one numbered folder, and `maxBytes` for jpeg, webp and avif.

The live tree is ahead of this research. The rename (packet 002) and the naming and placement hardening (packet 003) are complete in the working tree, the CLI (packet 004) is being built while this lineage ran with `runtime/src/dispatch.ts`, `runtime/src/cli.ts` and `runtime/src/core/probe-cache.ts` present as untracked files, and packets 005 and 006 are not started. The dispatch packet still says the folder is named `mcp server/`, and that line is stale: the folder is `runtime/` with the rename staged in the nested repository. That contradiction is recorded as finding 7 of iteration 1, and every citation in this lineage uses the live `runtime/` name.

## 2. Research Question

How should the Media Editor gain a `media-editor` CLI over the same 40 tool handlers its MCP server runs, how should the skill rely on that CLI alone while the Claude Project stays on MCP, and how should the naming and placement gate be hardened so a batch gets confirmed names and one place. The deliverable is a ranked, evidenced design for four implementation phases: rename `mcp server/` to `runtime/`, harden naming and placement, build the CLI, and move the skill to the CLI.

## 3. Fixed Decisions

- The Claude Code plugin ships the skill and the CLI runtime and registers no MCP server.
- The Claude Project stays on the Desktop extension and MCP, and gets the naming hardening.
- The skill's route order is the CLI first for everything it covers, then hand-written ffmpeg, then advice.
- No new tools for audio trim, loudness normalization or CRF compression. They stay on hand-written ffmpeg.

## 5. CLI Core (Iteration 1)

The transport-neutral dispatch exists and is the right shape. `dispatchTool(definitions, context, name, args)` at `runtime/src/core/dispatch.ts:105-162` takes a name-keyed tool map, a `ToolContext` and unknown args, and returns a discriminated `DispatchOutcome` of `result`, `unknown-tool` or `invalid-arguments`. It imports no transport value beyond the type `CallToolResult` at `:20`. The MCP adapter imports it back (`runtime/src/server/tool-registry.ts:15`) and maps the two failure outcomes to protocol errors (`:134-148`), while the CLI maps them to `INVALID_INPUT` JSON and exit 2 (`runtime/src/cli.ts:206-214`). Argument errors are results on the CLI and protocol errors on MCP, which is exactly the split each audience needs.

A separate entry was required because `runtime/src/index.ts:126` executes `void main()` at module scope. `runtime/src/cli.ts` is that entry, with a self-run guard at `:464-478`. Tool argv never reaches `loadConfig`: `configTokens` (`:216-246`) emits only `--allowed-dir` and `--output-dir` tokens, and tool arguments travel through `--args`, `--args-file` or stdin. This matters because `parseArguments` still turns bare tokens into allowed-root candidates (`runtime/src/core/config.ts:155-175`). Exit codes are a stable table: 0 success, 1 tool failure, 2 usage or dispatch error, 3 startup failure, 130 and 143 on SIGINT and SIGTERM (`cli.ts:310`, `:389`, `:203`, `:460`). Signal cleanup reaps children and tracked paths through `terminateAll` (`runtime/src/core/process-runner.ts:737-770`) and `registerCleanupPath` (`:705-725`).

## 6. CLI Surface and Output (Iteration 2)

The surface is `list`, `describe <tool>`, `health` and `<tool>` (`cli.ts:413-451`). `list` prints name, title and description for the 40 entries of `ALL_TOOLS`, and `describe` adds annotations plus `z.toJSONSchema(z.object(listedInputSchema(definition)))` (`:332-340`), using the existing zod `^4.6.5` with no new dependency. One JSON argument source per call (`--args`, `--args-file`, or stdin when not a TTY, `:248-278`), and individual tool flags are deliberately not accepted. stdout receives exactly `structuredContent` (`:388`), diagnostics go to stderr, and the exit code distinguishes outcomes.

The preview lands as a file: `PreviewSink` is a CLI-only context dependency (`runtime/src/server/tool-context.ts:112`, `:126`), `withPreviewBlock` returns `previewPath` instead of the base64 block (`runtime/src/tools/media/preview.ts:118-137`), and the sink writes `<dataDir>/previews/preview-<uuid>.jpg` atomically (`cli.ts:280-305`). Startup cost measured warm on this machine: 0.02 seconds baseline, 0.06 for the sharp import, 0.13 for the full tool graph, 0.11 for `node dist/cli.js list` end to end, so the build-time schema manifest the earlier draft proposed is not needed at this scale. The persistent cache landed as `<dataDir>/cache/probes.json` (`runtime/src/core/probe-cache.ts:53`, `:183-197`), and the shared `MEDIA_EDITOR_DATA_DIR` keeps `media_setup_ffmpeg`, `media_health`, previews and the cache in one folder across separate calls.

## 7. Distribution (Iteration 3)

The plugin build ships the CLI: `runtime/scripts/build-plugin.ts:363-367` fails when `server/dist/cli.js` is missing, and `:385-393` writes `bin/media-editor` (a POSIX shim that resolves its own real path and runs `node "$here/../server/dist/cli.js"`) plus `bin/media-editor.cmd`. `runtime/package.json:9-12` declares `media-editor-mcp` and `media-editor` bins for the standalone route, and the package stays private. The bundle stages `dist`, `assets` and `licenses` whole (`runtime/scripts/build-bundle.ts:76`), so the CLI rides along, well under the 150 MB limit (`scripts/bundle/targets.ts:29`).

Both plugin-mechanics questions were answered from the official documentation rather than assumed. `${CLAUDE_PLUGIN_ROOT}` resolves inline in skill Markdown and is not present in the Bash environment (https://code.claude.com/docs/en/plugins-reference, the Environment variables section and its resolution table). A plugin `bin/` folder is on the Bash tool's PATH while the plugin is enabled, and claude.ai and Cowork do not install a plugin that has it (same URL, the Standard layout table). The bare `media-editor` command is therefore the Claude Code route, with the recorded cost that claude.ai and Cowork will not install this plugin, and the plugin-root form remains the portable alternative a skill can carry. Plugin skills load from `<plugin>/skills/<skill-name>/SKILL.md` and are namespaced (https://code.claude.com/docs/en/skills). Per-platform sharp and the pinned ffmpeg need no new work (`runtime/scripts/test-pinned.ts:83-122`), and the dist layout must stay because `runtime/src/server/server-info.ts:42` and `runtime/src/core/font-path.ts:51` read relative paths from `import.meta.url`.

One distribution item is still pending: `runtime/claude-plugin/.claude-plugin/plugin.json` still carries the `mcpServers` block pointing at `server/dist/index.js`, and `runtime/claude-plugin/README.md` still describes the MCP delivery. Removing the block is phase 005's deliverable.

## 8. Skill and Project Split (Iteration 4)

The split is forced into one shape by three measured constraints. Invocation text cannot live in a paired file because the Project cannot run the CLI, so it belongs in a new skill-only `sk-media-editor/references/cli.md` declared unmirrored. That file must not enter `RESOURCE_MAP` or `ALWAYS`, because `benchmark/router/differential.py` compares resource lists field by field and a skill-only entry would fail every fixture. It is reached through `SKILL.md`'s resource table instead. `setup.md` stays one mirrored file with a section per surface, which is operator decision OD-4 (`AI Systems/Media Editor/specs/005-media-editor-cli-runtime/001-deep-research/spec.md:214`).

All seven declared mirror pairs were byte-identical at this reading, verified with `cmp -s` (`systems.py:1252-1267` declares them, with `router-contract.md` the declared unmirrored exception at `:1271-1276`). The route change is `media_cli_available()` as the first branch of `choose_route` (`sk-media-editor/references/router-contract.md:147-155` and the kernel copy at `systems.py:1680`), bound rather than reimplemented so the kernel's copy stays byte-identical modulo comments. That forces a fourth host state and a third binding in `differential.py:100-104` and `:314-322` (no schema change, because `route` is not a contract field), a CLI-first rewrite of the five tools-first phrases in `benchmark/gates/rule_parity.py:71-95` with `min_pairs` raised in the same change, and a re-scope of the `SRO-001` and `PRO-001` twin in `benchmark/grader/twin_divergence.py:89-97` to assert the deliverable while the route assertion moves to the unpaired sets. The Sync Loop declaration needs three edits: `references/cli.md` into `unmirrored_sources` at `systems.py:1271-1276`, the header statement at `:1290` rewritten (it is wrong twice), and the router statement at `:1680`. The "CLI runtime" phrase in the playbook must be reworded to "the Claude Code skill" wherever it means the runtime, keeping CLI for the executable.

## 11. Ruled-Out Directions

- A second copy of the dispatcher for the CLI, or a duplicate CLI handler table. The placement split and error mapping would drift apart.
- Keeping the CLI coupled to the MCP SDK at runtime, or printing the whole `CallToolResult` to stdout.
- Driving `createServer` over an in-process transport for a one-shot call, argv sniffing inside `index.ts`, or teaching `loadConfig` about CLI separators.
- A build-time schema manifest, per-flag tool arguments, base64 previews in JSON, or a resident daemon before startup measurements.
- A baked absolute path in the skill copy, a second MCP server entry for the CLI, npm publication, or a single-file CLI bundle that relocates `import.meta.url`.
- Splitting `setup.md` by surface, adding `cli.md` to `RESOURCE_MAP` or `ALWAYS`, reusing the `tools` route value for a CLI run, or a skill-only `choose_route`.
- A hard server guard against unconfirmed names, `maxBytes` as a hard guarantee, multi-input `image_convert` in place of `targetFolder`, or relying on the model to notice a missing `subfolder`.
