**`media_probe` — what to report**
- Core contract: "Inspect: read streams, duration and format with `ffprobe`" (`references/mcp-video-audio.md:75`); "Inspect the source with `ffprobe`" (`:49`); `ffprobe` "covers inspection" and ships with FFmpeg (`:41`). So the probe output is: streams, duration, format.
- Preconditions/health fields to expose: `ffmpeg -version` (`references/mcp-video-audio.md:37-39`; `SKILL.md:261`), `ffprobe -version` "when the operation needs metadata" (`SKILL.md:262`).
- Capability truth to report (probe-grade): `ffmpeg -encoders | grep -E "libx264|libx265|libvpx|aac|libmp3lame"` (`references/mcp-video-audio.md:56-58`) and `ffmpeg -filters | grep -E "drawtext|subtitles|ass "` (`:80-82`); the skill mandates these checks before promising encoders/filters (`SKILL.md:263-264`, "Never promise a capability the installed build cannot deliver", `SKILL.md:268`).
- ffprobe is also "first-pass diagnosis in Repair Mode" (`SKILL.md:395`).
- Cross-ref (outside the three mandated files): the concrete entries recipe `ffprobe -v error -show_entries stream=width,height,codec_name,pix_fmt -of default=noprint_wrappers=1 INPUT.jpg` lives in `references/mcp-imagician.md:150-152` per inventory `source-inventory.md:264`; the field set to return (`duration, has_video, has_audio, width, height, avg_fps, sample_rate, channels, channel_layout` + image fields) is defined in the inventory H from `vam/server.py:1244-1262` / `imagician/src/index.ts:376-387`.

**`media_repair` — which repairs, which flags**
- Mode contract (SKILL.md repair mode): activation "Repair or diagnose a broken media file" (`SKILL.md:39`); `$repair`/`$r` → "Repair Mode with ffprobe diagnosis then ffmpeg repair" (`SKILL.md:48`); route "`ffprobe then ffmpeg`" (`SKILL.md:86`); keyword weights repair 4 / broken 3 / corrupted 3 / recover 3 (`SKILL.md:140`); routed resource `references/interactive-intelligence.md` (`SKILL.md:148`); "Repair hands off from ffprobe to ffmpeg once diagnosis names the fault" (`SKILL.md:151-153`); `TOOL_MAP "REPAIR": "ffprobe and ffmpeg"` (`SKILL.md:159`); mode table: "ffprobe then ffmpeg | Diagnose and fix a broken media file" (`SKILL.md:279`).
- The only concrete "recover-by-rewrite" commands in scope (generic conversion recipes a repair tool composes after diagnosis):
  - Remux-only container rewrite: `ffmpeg -i INPUT.mov OUTPUT.mp4` (`references/mcp-video-audio.md:90-92`, "picks sensible defaults for the container" `:94`).
  - Explicit-encode remux: `ffmpeg -i INPUT.mov -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k OUTPUT.mp4` (`:96-98`).
  - Stream-copy rewrite/trim: `ffmpeg -ss 00:00:30 -to 00:02:00 -i INPUT.mp4 -c copy OUTPUT.mp4` (`:102-104`); "`-c copy` is fast and cuts at the nearest keyframe. Drop `-c copy` for a frame-accurate cut at the cost of a re-encode" (`:106`); "`-c copy` keeps quality and speed but cuts at keyframes and cannot change the encoding" (`:243`).
  - Fallback principle: "Re-encode when they differ" (`:115`); container/codec pairing rule `:209`.

**`video_hls_ladder` — full recipe** (from `assets/hls-video-conversion.md` v0.111)
- Renditions: 4 rungs — 1080p (1920x1080), 720p (1280x720), 480p (854x480), 360p (640x360) (`:51`, `:97-100`, quality table `:151-156`).
- Geometry per rung: `[vN]scale=w=W:h=H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2[vNout]` — downscale-only, centered pad (`:97-100`, rationale `:121`). Fan-out: `[0:v]split=4[v1][v2][v3][v4]` (`:96`, "duplicates the video stream four times" `:121`).
- Codec settings per rung (`:101-108`): `-map "[vNout]" -c:v:N libx264 -preset fast -tune fastdecode` + `-crf 23` + `-g 48 -keyint_min 48 -sc_threshold 0`; 1080p/720p: `-profile:v main -level 4.0`; 480p/360p: `-profile:v baseline -level 3.1`. Bitrates: `-maxrate:v:N` 2500k / 1500k / 800k / 500k; `-bufsize:v:N` 5000k / 3000k / 1600k / 1000k (bufsize = 2× maxrate, `:121,169`).
- Audio: `-an` drops audio (`:109`, "20-30% size savings" `:56`).
- Segment length: `-hls_time 2` (`:111`); policy "2 seconds recommended… 4 seconds reduces files but slows switching. 6 to 10 seconds is not recommended" (`:170`); "2-second segments for fast initial playback" (`:56`).
- Mux + playlist naming (`:110-118`): `-f hls -hls_playlist_type vod -hls_flags independent_segments -hls_segment_type mpegts -hls_segment_filename "OUTPUT_DIR/%v/segment_%03d.ts" -master_pl_name "master.m3u8" -var_stream_map "v:0,name:1080p v:1,name:720p v:2,name:480p v:3,name:360p" OUTPUT_DIR/%v/playlist.m3u8`.
- Output structure (`:77-86`): `master.m3u8` + per-rung dirs `1080p/ 720p/ 480p/ 360p/` each holding `playlist.m3u8` + `segment_*.ts`. ⚠ Doc-internal inconsistency: `:72` calls variants `stream_1080p.m3u8`, but the actual command emits `%v/playlist.m3u8` (`:118`) — the command is authoritative.
- GOP rule: "framerate times segment duration. At 24fps with 2-second segments, GOP is 48" (`:168`; `-g 48` rationale `:121`).
- Quality knobs: CRF 0–51 — 18 visually lossless, 23 recommended ("visually transparent", `:121`), 28 medium, 20–22 premium, 24–26 bandwidth-limited (`:158`). Bandwidth routing: >3 Mbps→1080p, 1.5–3→720p, 700k–1.5M→480p, <700k→360p (`:160`).
- Single-rung variant (`:125-136`): `-vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2" -c:v libx264 -preset fast -tune fastdecode -profile:v main -level 4.0 -crf 23 -maxrate 2500k -bufsize 5000k -g 48 -keyint_min 48 -sc_threshold 0 -an -f hls -hls_time 2 -hls_playlist_type vod -hls_flags independent_segments -hls_segment_filename "OUTPUT_DIR/segment_%03d.ts" OUTPUT_DIR/playlist.m3u8`.
- 10-second smoke test (`:140-145`): `ffmpeg -i INPUT_VIDEO.mp4 -t 10 -vf "scale=1920:1080" -c:v libx264 -preset fast -crf 23 -maxrate 2500k -an test_output.mp4`.
- Web opts: `-movflags +faststart`, `-an`, 2-second segments (`:56`). Prereq check: `ffmpeg -version` (`:41-43`); libx264 verify `ffmpeg -codecs | grep 264` (`:240`). Troubleshooting: size → CRF 26 / maxrate 2000k / drop 1080p (`:242`); quality → CRF 20 / maxrate 3000k / `-preset medium` (`:243`). GPU substitutes for `-c:v libx264`: `h264_nvenc`, `h264_qsv`, `h264_videotoolbox` (`:248`). Batch pattern (multi-file, `OUTPUT_BASE="hls_output"`) at `:176-229` — single-file ladder first per inventory H:285.
